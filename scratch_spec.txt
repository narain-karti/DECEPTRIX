What the name means
DECEPTRIX stands for DEception, Content, Evidence, Provenance, Trust, Risk Intelligence eXchange. It describes a platform that collects independent evidence and returns an auditable risk assessment instead of a black-box verdict.
1. MVP decision
The five-day MVP is a web application with two investigation modes: Media Audit for short videos and Rumour Audit for pasted social-media claims. Both produce a timestamped or claim-level evidence report, show uncertainty, cite sources, and never claim to be a legal certificate of truth.
MVP north star
A judge can upload a 60-second clip or paste a rumour, understand what DECEPTRIX found, inspect evidence, and download an audit report in one guided demonstration.
In scope
Video upload, validation, hash, metadata inspection, sampled frames, one real visual-manipulation detector, evidence timeline, JSON report, and print-ready HTML/PDF report.
Rumour textbox for English text: claim extraction, official-first evidence retrieval, source cards, and one of five cautious outcomes: supported, contradicted, context missing, no authoritative coverage, or inconclusive.
A connector boundary that can later support government data, fact-check systems, search providers, document verification, and partner applications.
Three fixture demos: suspected manipulation, no-conclusive-evidence media, and a government-policy rumour supported or contradicted by authoritative sources.
Explicitly out of scope for five days
User accounts, teams, public multi-tenant deployment, live-streaming, long videos, training a new model, universal AI-writing detection, URL media downloading, fully automated web crawling, and any automatic moderation or takedown action.

Media Audit data flow
POST /api/v1/media/jobs receives the file after type and size checks; create case_id and SHA-256.
Run ffprobe for duration, codecs, resolution and stream checks; FFmpeg extracts a mono 16 kHz WAV and thumbnails.
Frame planner selects uniform samples, scene boundaries, and face-containing frames. It records coverage so missing faces are never hidden.
A single pinned, pretrained visual-manipulation detector scores eligible frames. Its adapter turns raw results into evidence events.
A provenance adapter reports verified, invalid, absent, unsupported, or unavailable. Absent credentials are informational, not suspicious.
Optional semantic analyzer receives small frame batches and returns strict JSON observations. It remains advisory unless evaluated.
Fusion evaluates evidence quality and disagreement, creates a cautious label, and builds report JSON/PDF.
Rumour Audit bridge architecture
The rumour service is a retrieval-and-evidence system, not an LLM that decides truth. Search is used to discover candidate sources; only retrieved source passages and configured source policy can support a displayed conclusion.

Source policy for the MVP
Tier
Use
Examples / implementation note
Tier 1: primary authority
May support or contradict a claim.
Official ministry, regulator, election authority, statutory body, gazette, government dataset, or original institution publication.
Tier 2: official fact-check
Strong reusable evidence where scope matches.
PIB Fact Check for Government of India matters; Google Fact Check Tools API claim-search results when available.
Tier 3: discovery only
Find leads; cannot alone determine the result.
SerpApi Google/News results, reputable news reports, social posts, blogs.
Tier 4: untrusted
Never use as final evidence.
Anonymous accounts, repost aggregators, screenshots without original source, unsourced forwards.
Critical product rule
DECEPTRIX may say “no authoritative coverage found” after bounded search. It must not say a rumour is true merely because it found no contradiction, and it must not use SerpApi ranking as evidence.
4. Core schemas and API contracts
EvidenceEvent - shared media and text contract
Required fields: event_id, case_id, modality, type, status, score_or_null, severity, confidence_quality, scope, explanation, source_refs, artifact_refs, model_or_connector, version, limitations, created_at. The status field is completed, unavailable, failed, or not_applicable.

Verdict rules
Media: “Likely manipulated” requires high-quality, localized evidence from the selected detector; otherwise use “Inconclusive” or “No significant technical anomalies detected in analyzed coverage.”
Media: show provenance separately. “No credentials found” is neither proof of authenticity nor manipulation.
Text: outcomes apply to one atomic claim, not the entire pasted message. An audit may contain mixed outcomes.
Text: every conclusion includes a source list and a “what could change this assessment” note.

Daily integration rule
Every day ends with one vertical slice on the shared branch: upload or paste -> real API -> stored case -> rendered result. No team member should spend more than one day building a module that cannot produce a shared evidence object.
6. Build steps from zero
Create a monorepo: apps/web, services/api, packages/contracts, storage, fixtures, docs. Add README and .env.example before writing features.
Define Pydantic models and TypeScript types for Case, EvidenceEvent, Claim, SourceRef, AuditOutcome, and Report. Generate or hand-maintain a single contract file.
Create FastAPI health route and Next.js landing page; make them communicate locally.
Implement media intake and a mock worker. Do not integrate a model until the job/result lifecycle works.
Implement preprocessing with safe subprocess calls to ffprobe/FFmpeg; capture stderr and return error codes, never shell-concatenate user filenames.
Integrate one model with a locked weight/version and an adapter test using a fixture. Persist raw model score separately from display label.
Implement Text Audit with a fixture-backed connector first; then add real connector calls using environment variables and source allowlists.
Build fusion as pure, tested functions. Reports consume only normalized evidence, never raw model or LLM text.
Generate JSON first, then render the same structured report as HTML/PDF.
Run fixture tests and practice the complete demo offline. Capture screenshots and create a backup recorded demo.
7. Test, safety, and demo checklist
Area
Must test before judging
Validation
Oversized, unsupported, corrupt, and no-video files show useful errors; pasted text limits and empty state work.
Partial failure
One unavailable model or connector leaves a truthful partial report rather than a failed case.
Evidence integrity
Every displayed score has a detector/connector/version; every text conclusion has citations.
Privacy
Temporary media is deleted after the demo window; no API keys, user files, or private source content appear in logs.
Honesty
No “AI-generated text” claim based only on writing style; no “authentic” label from absence of evidence.
Demo resilience
Prepared fixtures, local fallback results, and a short backup video exist if network/API inference fails.
